Transport chosen:
- The retry feedback is transported through the existing orchestrator state file passed as --state-path.
- Reason: reciprocal-implement.mjs already receives and parses that file to recover currentItem, and reciprocal-orchestrator.mjs already persists bounded failures there. Reading state.failures avoids adding another state file or side channel.
- reciprocal-orchestrator.mjs now stores attemptCommit on each failure when an implementation commit existed, and logs feedbackDeliveredVia: "state.failures" with feedbackBytes.

Literal retry-prompt section:

=== RETRY FAILURE FEEDBACK - FIX THIS FIRST ===
Wishlist item: <item id>
Retry round: <failures.length + 1>
Previous attempt commit: <failure.attemptCommit or state.lastImplementCommit or state.acceptedSourceSha or unknown>
Failed command: <failure.command>
Exit code: <failure.exitCode>
Output shown below is the tail, truncated to 6000 bytes so the item text remains visible.

The previous attempt failed verification. Your first priority is to fix the reported failure below.
Do not restart the item from scratch unless the failure proves the previous approach is unusable.

Captured failure output:
```text
<captured failure output tail>
```
=== END RETRY FAILURE FEEDBACK ===

If the captured output is within the 6000-byte bound, the prompt instead says:
"Output shown below is the complete captured output."
