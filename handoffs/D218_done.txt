Provisioning strategy:
- Chosen default: link the main repo's node_modules into the isolated implementer worktree.
- On Windows the link is a directory junction via fs.symlinkSync(source, target, "junction").
- On non-Windows the link is a directory symlink via fs.symlinkSync(source, target, "dir").
- Reason: junction/symlink provisioning is effectively instant and avoids a per-round npm ci or a 568 MB node_modules copy. That matters because reciprocal rounds run unattended on a short cadence.
- Fallback behavior: if the source node_modules is missing, already present, or the link cannot be created, the implementer round does not abort. reciprocal-implement.mjs records dependencyProvisioning as missing/present/degraded and the prompt tells the implementer that self-checks may be unavailable while the orchestrator remains authoritative.

Cleanup safety:
- cleanupIsolatedWorktree now calls removeIsolatedDependencyLink(worktree) before git worktree remove and before rmSync(parent, { recursive: true, force: true }).
- removeIsolatedDependencyLink only unlinks worktree/node_modules when lstat reports a symlink/reparse link, or when realpath(worktree/node_modules) equals realpath(repo/node_modules).
- If that unlink cannot be performed, cleanup throws before recursive parent deletion with: "refusing to delete isolated worktree parent because dependency junction could not be unlinked first".
- This fail-closed behavior leaves a temp worktree behind rather than risking recursive deletion through the junction into the real repo dependencies.
- Test proof: "cleans up the isolated node_modules junction without deleting the real dependencies" links fixture node_modules to the real repo node_modules, runs a real implementer round, lets cleanup execute, then asserts the real node_modules still exists and remains non-empty with the same top-level entry count.

Shared dependency mutation risk:
- A junction means writes under worktree/node_modules would write into the real repo node_modules.
- I did not copy node_modules because that is slow and wasteful for the unattended loop, and Windows directory read-only attributes are not a reliable protection for package contents.
- Mitigation implemented: the implementer prompt and Claude system prompt now explicitly forbid npm install, npm ci, pnpm install, yarn install, and package-manager commands that mutate dependencies. The D215 full-test/git prohibitions remain.
- Residual risk: a malicious or badly behaving implementer with Bash could still intentionally mutate files under node_modules. The current risk is accepted because the implementer is instructed narrowly and the junction keeps the loop usable; the orchestrator's real-repo verification remains authoritative.
